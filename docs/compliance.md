# 合规与风险说明（请先读一下）

> **这不是法律意见。** 下面是 CCBaton 作者对 Anthropic 公开条款的理解，写于 2026-11-27，2026-11-28 发版前对照三处原文复核过。条款会更新，对条款的解释权在 Anthropic，**请以 Anthropic 最新的说明为准**。CCBaton 是非官方工具，和 Anthropic 没有任何关系，也没有得到过它的许可。

## 先说结论

- 同时使用**自己名下的多个**订阅账号，Claude Code 官方文档是明确支持的，推荐的做法就是给每个账号一个独立的配置目录（`CLAUDE_CONFIG_DIR`）。CCBaton 的「终端」按钮用的就是这个做法。
- CCBaton 的「切换」（把登录搬进默认位置，让正在运行的 `claude` 换号）、**额度预热**、**Claude 桌面端账号切换**，官方文档没有专门讲到，属于**灰色地带**，越往后越灰。后两项默认关闭。
- **没有任何工具能保证不封号。** 如果你只想用官方文档写明的方式，看下面的「只用官方写明的方式」。

## 官方的相关规定

1. **消费者服务条款**（[原文](https://www.anthropic.com/legal/consumer-terms)）里和我们相关的几条：
   - 不得与他人共享账号登录信息或凭据，也不得让别人使用你的账号；
   - 不得通过机器人、脚本等**自动化或非人工**的方式访问服务（用 API 密钥或 Anthropic 明确允许的方式除外）；
   - 不得**绕过**系统或保护措施。
2. **Claude Code 法律与合规页**「Authentication and credential use」一节（[原文](https://code.claude.com/docs/en/legal-and-compliance)）：
   - 订阅登录（OAuth）只给订阅者本人，用于**普通的**使用；
   - 第三方开发者不能把 Claude.ai 登录做进自己的应用，也不能拿用户的订阅凭据替用户转发请求；
   - 开发者**不得收集、存储或中转** Claude.ai 的凭据或会话令牌，登录必须走 Anthropic 自己的流程；
   - 不妨碍用户用自己的订阅登录**未经修改的** Claude Code；
   - Anthropic 保留不事先通知就采取措施的权利。
3. **Claude Code 认证文档**「Log in with multiple accounts」一节（[原文](https://code.claude.com/docs/en/authentication)）：想同时登录多个账号（比如工作号和个人号），就给每个账号一个独立的配置目录，启动 `claude` 时用 `CLAUDE_CONFIG_DIR` 指向它。
4. Pro、Max、Ultra 的额度说明里写着，额度是以**普通的个人使用**为前提的。这句话没有说清楚「自己名下几个订阅轮着用」算不算普通使用，作者没有找到官方对此的明确说法。

## 逐条对照：CCBaton 是怎么做的

| 官方要求 | CCBaton 的做法 |
|---|---|
| 登录走 Anthropic 自己的流程 | 添加账号时在终端里运行 Claude Code 官方的 `claude auth login`，授权在官方页面完成。桌面端的登录也是在 Claude 桌面应用自己的官方登录界面里完成。CCBaton 自己没有登录界面，也没有 OAuth 客户端。 |
| 不替用户转发请求 | CCBaton 不拿令牌发任何请求，没有服务器。它自己只在检查软件更新时访问 GitHub（只带软件名和版本号）。额度和预热消息都是你本机的 `claude` 自己发的。 |
| 不收集、存储、中转令牌 | **终端：** 令牌始终只在 macOS 钥匙串里，用系统自带的 `security` 命令搬动，CCBaton 自己的文件里不存令牌；不上传、不联网。<br>**桌面端（可选，默认关）：这一条是例外。** 它会把 Claude 桌面应用**自己加密过**的登录副本（`config.json` 里的三个键加网页登录的 `Cookies`）存在 CCBaton 的目录里，权限 0600，不解密、不上传。这是最接近上面第 2 条「不得存储令牌」的地方，请你自己权衡。 |
| 只供本人正常使用 | 只管你自己的账号；每次切换都是你手动点的；**不做自动轮换、不按额度自动换号、不并发共用、没有共享账号的功能**。 |
| 不修改 Claude Code | 不改 Claude Code 程序本身。「终端」按钮用的是官方文档教的 `CLAUDE_CONFIG_DIR`；挡住第三方接口时用 `claude --settings` 参数覆盖，不改你的任何设置文件。 |
| 不绕过保护措施 | CCBaton 不伪造请求、不改请求头、不碰网络；每个请求都是你本机的 `claude` 用你自己账号的登录正常发出的，没有技术上绕过任何限制。一个账号的额度用完了，改用你**自己名下的另一个付费账号**接着用，是多账号用户的正常需求，用完的那个账号的额度并没有被改变。CCBaton 不做、也不建议的是：自动轮换、批量注册账号来叠加额度、用别人的账号。 |
| 令牌的刷新和吊销 | CCBaton **不刷新令牌**：读额度时运行的是 `claude -p /usage`（不问模型、不花额度），由 Claude Code 自己刷新令牌、自己写缓存。**不登出、不吊销**：移除账号只删本机上的登录，不会让令牌作废；桌面端「清除登录」也只是删本地的键，不是退出登录。 |

## 三档风险：哪些是官方写明的，哪些不是

**1. 官方文档写明的做法**
- 「终端」按钮：每个账号一个独立的 `CLAUDE_CONFIG_DIR`，在里面运行 `claude`，几个账号可以同时开。这和官方文档的推荐写法一样，只是 CCBaton 替你建了目录、开了终端。
- 额度查看：读 Claude Code 自己缓存的额度，需要时运行一次 `claude -p /usage`（0 额度）。

**2. 官方没有专门讲到的做法（灰色）**
- **「切换」**：把目标账号的登录搬进 Claude Code 默认读的位置，原来的账号收回自己的位置，这样正在运行的 `claude` 和新开的终端都会用新账号。令牌始终在本机钥匙串里，不离开你的电脑；官方文档没有讲到这种用法。

**3. 更灰，所以默认关闭**
- **额度预热**：自动运行 `claude -p "hi" --model haiku` 发一条很短的消息来让 5 小时窗口开始计时。这是明确的**自动化**使用，和条款里「不得用脚本等自动化方式访问」那一条最接近。默认关闭，开不开由你决定。
- **Claude 桌面端账号切换**：保存桌面端登录的加密副本、退出并重新打开 Claude、同步 Code 标签的对话列表。它最接近「不得存储会话令牌」那一句，也依赖桌面应用内部的文件结构。设置里有总开关，默认关闭。

### 只用官方写明的方式

如果你只想用官方文档写明的方式：
- **只用「终端」按钮**开终端，不点账号卡片上的「切换」；
- 不开额度预热；
- 不开桌面端总开关。

这样 CCBaton 就只是帮你建了几个 `CLAUDE_CONFIG_DIR` 目录，并把它们的额度摆在一起看。

## 我们刻意不做的

- 自动切换账号、按额度自动轮换；
- 多个账号并发地分摊请求，或者任何形式的路由、聚合、转发；
- 共享账号、把你的登录交给别人用；
- 替你登录、保存你的密码、绕过两步验证；
- 修改 Claude Code 或 Claude 桌面应用的程序文件。

## 常见问题

**一个账号的额度用完了，换另一个自己的账号接着用，算「绕过限制」吗？**
作者的理解是**不算**，这是多账号用户最正常的用法：每个订阅各有自己的额度，你是在使用另一份自己买的额度，没有任何技术手段去改动或欺骗系统，条款禁止的「绕过系统或保护措施」说的是技术上的规避。官方认证文档也明确支持一个人同时登录多个账号。但有两点要说清楚：这只是作者对条款的理解，**Anthropic 没有就这种用法给过明确的说法**；而**自动化地**在账号之间轮换、专门注册很多账号来叠加额度、使用别人的账号，离「普通的个人使用」就远了，CCBaton 不做这些，也请你不要这样用。

**能保证不封号吗？**
不能。Anthropic 如何识别和处理账号，有很多 CCBaton 看不到的因素（比如账号的注册和支付情况、使用模式、网络等）。CCBaton 只能保证：切换本身用的是上面写的方式，不转发请求、令牌不出本机。到目前为止，作者没有看到 Anthropic 针对这类个人换号工具采取行动，但这不是官方许可，以后也可能变。

**公司给的账号（Team / Enterprise）可以用吗？**
请先问你们的管理员或看公司的使用规定。企业账号可能有额外的安全和合规要求，CCBaton 不了解你们公司的规定。

**用这个工具出了问题谁负责？**
CCBaton 是 MIT 许可的开源软件，按「原样」提供，不提供任何担保，详见仓库里的许可证。请自己评估风险，多个账号请都是你自己的订阅。

**条款改了怎么办？**
作者会尽量跟进，但不保证及时。如果官方明确不允许某种做法，对应的功能会被关闭或删除。发现本文和最新条款对不上，欢迎到 [Issues](https://github.com/SoKeiKei/ccbaton/issues) 告诉作者。
